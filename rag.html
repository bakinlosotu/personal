What is happening?
The document is being prepared for retrieval. The system will split it into smaller pieces called chunks. At this stage, the LLM does not need to learn or memorise the document.

Important distinction:
The chunk is the actual text. The embedding is a numerical representation of its meaning. The vector database stores both so that relevant information can later be retrieved.

Generation ≠ retrieval.
The retrieval system finds useful evidence. The LLM uses that evidence to generate a natural language response.

🧠 The big idea to remember

RAG is not the LLM learning your document. Your document is chunked, embedded and stored in a searchable vector database. When you ask a question, your question is embedded too. The system retrieves the most relevant chunks and passes those chunks to the LLM. The LLM then uses the retrieved context to generate the answer. In simple terms: Store → Search → Retrieve → Give context to LLM → Generate
